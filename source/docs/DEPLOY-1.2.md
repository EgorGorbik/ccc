# Falcon Time 1.2 — подготовка к деплою

Дата: 1 октября 2026. Целевая среда: существующий приватный Sites / Cloudflare Worker, D1 `DB`, R2 `BUCKET`.

Эта версия подготовлена и сохранена для следующего деплоя. Подготовка не изменяет работающий сайт и его базу. Кошелёк остаётся в отдельном Falcon Messenger.

## Что входит в релиз

- Отдельные серверные модули проверки HTTP-запросов, входа и диагностики готовности.
- Версия доступа `auth_version`: смена личного кода и отключение сотрудника отзывают браузерные сессии и ранее выданные OTP. Уже начатый вход со старой версией не создаёт новую действующую сессию.
- Первичная привязка аккаунта, отзыв доступа, административные решения, ручное время и журнал выполняются атомарно в D1 batch.
- Исправления времени заменяют исходный интервал и сохраняют поздно поступившие соседние интервалы. Производные конфликтные фрагменты не редактируются напрямую.
- Проверка порядка событий устройства включена в атомарную запись. Повтор доставки не удваивает время, конфликт сохраняется на проверку.
- Архивирование раз в сутки при активности работает независимо от ручного создания копий и использует общую блокировку с бэкапом.
- JSON ограничен 100 000 байт при чтении потока, методы проверяются, ошибки получают `X-Request-ID`, диагностические логи не содержат содержимого запросов и кодов.
- Отчёты администратора не создают SQL-список параметров на всех работников.

## Сборка и проверка

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm build
```

`pnpm check` проверяет TypeScript, расчёт времени/DST, API на отдельной SQLite, расширение, конкурентные запросы, откат при ошибках хранения, обновление заполненной схемы и реальное восстановление JSON через Python CLI. Почта и R2 в тестах подменены. Python 3 требуется для теста восстановления и самого CLI, но не для Worker.

Хостинговый архив должен собираться штатным Sites workflow из того же коммита, который сохранён в источнике. Исходники, `.env`, тестовые базы и ключи в Worker-архив не включаются.

## Миграция

Новая миграция: `drizzle/0004_backend_integrity.sql`.

Она добавляет `auth_version INTEGER NOT NULL DEFAULT 0` в `people`, `logins`, `login_codes` и индексы для истории изменений, бэкапов, исправлений. Существующие профили и сессии сохраняются; исторические миграции 0000–0003 не изменены. Перестроения и удаления таблиц нет.

Перед боевым деплоем:

1. Сделать и скачать проверенную резервную копию из кабинета владельца.
2. Убедиться, что версия сохранена с проверенным архивом, D1/R2 привязаны к существующему проекту и приватный доступ сохранён.
3. Применять миграции только штатным механизмом Sites; затем загрузить Worker из сохранённой версии.
4. После публикации войти владельцем и проверить `GET /api/readiness` в той же авторизованной сессии.
5. Проверить реальное подключённое устройство: новое действие, синхронизация, отчёт, остановка/возобновление. Это эксплуатационная проверка; тесты с подменами её не заменяют.

На этой стадии боевые миграции, рассылки, платёжные операции и изменения сервера .14 не выполнялись.

## Диагностика готовности

`GET /api/readiness` требует входа в платформу и профиль owner/admin. Для сотрудника — 403. Проверяет наличие нужных таблиц/столбцов D1, чтение R2 через HEAD без создания объекта, настройку почты и возраст последней копии.

- 200 и `ready: true`: обязательные проверки D1/R2 пройдены.
- 503 и `ready: false`: обязательный компонент недоступен или нужна миграция.
- `email_not_configured_personal_codes_available`: почта не подключена; работают личные коды.
- `first_backup_required` / `backup_older_than_48_hours`: нужна резервная копия.

Нельзя считать `ready: true` подтверждением доставки реального письма, фонового cron или фактического сбора активности работников. API не раскрывает секреты и не требует их передачи в URL.

## Переменные среды

Обязательны логические привязки `DB` и `BUCKET` в manifest. Для одноразовых кодов по почте дополнительно нужны секрет `RESEND_API_KEY` и проверенный отправитель `MAIL_FROM`. Значения задаются через настройки среды, не через git.

Отдельные домены ChatGPT в расширении и origin Falcon Time уже настроены на действующий адрес. При переносе адреса требуется пересобрать расширение; его версия в этом backend-релизе не меняется.

## Откат

Старый Worker не учитывает версии доступа. После применения 0004 и выполнения ротации **не возвращать старую авторизацию** как автоматический rollback: это может ослабить отзыв доступа. При проблеме остановить публикацию и подготовить исправленную версию с сохранением схемы и проверок `auth_version`.

Миграции применяются до Worker: не переписывать уже применённый SQL и не удалять новые столбцы. При повреждении данных восстановить копию сначала в новую изолированную базу командой `python scripts/restore-backup.py backup.json restored.sqlite`, проверить итоги и только затем планировать переключение. Скрипт не перезаписывает существующую базу и отключает старые устройства/коды сотрудников.

## Оставшиеся эксплуатационные ограничения

- Проверка активности требует установленного расширения на компьютере; мобильный ChatGPT не измеряется.
- Резервирование и обслуживание запускаются синхронизацией, а не круглосуточным cron.
- Реальная доставка почты требует настроенного отправителя и проверки после подключения.
- Локальные тесты используют SQLite и подмены Cloudflare: реальные задержки и квоты D1/R2 проверяются после деплоя.
- Текущая версия рассчитана на доверенный шлюз авторизации Sites. Для обычного VPS/Docker нужна отдельная адаптация авторизации и хранилища.
