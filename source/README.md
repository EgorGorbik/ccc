# Falcon Time

VPS deployment for `falconai.time`: see [the Russian deployment guide](docs/DEPLOY-VPS-RU.md). `pnpm run build:vps` builds a production Node standalone server; `compose.yaml` uses isolated SQLite and backup volumes. Existing Sites deployment is a separate runtime.

Учёт времени сотрудников в ChatGPT: кабинет руководителя и администратора, личные профили, расширение Chrome/Edge и мобильный просмотр отчётов.

## Правила учёта

- Первое действие в активной вкладке ChatGPT начинает сессию. Содержимое сообщений, конкретные клавиши и файлы не записываются.
- Последнее действие + 30 минут — расчётный выход; эти 30 минут включены в итог. Открытая сессия не начисляет будущие минуты.
- Смена проекта закрывает предыдущий интервал. Устройства одного сотрудника объединяются без двойного начисления.
- Ручная остановка действует на всех устройствах до явного возобновления. Офлайн-остановка сначала останавливает локальный сбор и передаётся серверу после восстановления связи.
- Периоды: день, неделя с понедельника, месяц и год. Часовой пояс отчётов America/New_York, включая DST.

## Подключение команды

1. Владелец открывает кабинет через ChatGPT и задаёт свой личный код. Кабинет привязывается к этому аккаунту платформы.
2. В разделе «Команда» выдаёт Юре и Даниилу личные коды. Юра — администратор, Даниил — сотрудник. Можно добавлять остальных работников.
3. Каждый сотрудник выбирает себя, входит по своему коду и заполняет анкету, подтверждая подключение учёта.
4. В «Подключение» скачивает ZIP расширения. Распаковывает и загружает папку через режим разработчика в Chrome/Edge.
5. Оставляет кабинет открытым в отдельной вкладке своего профиля браузера и нажимает «Подключить» в расширении.
6. Для неизвестного чата выбирает проект. В распознанных URL проектов `/g/g-p-…` выбор распространяется на остальные чаты этого проекта; неподтверждённый контекст остаётся «Без проекта».

Раздельные профили браузера обязательны при использовании компьютера несколькими работниками. Проверка API удостоверяет профиль Falcon Time; аккаунт внутри каждой вкладки ChatGPT автоматически не удостоверяется. Открытие кабинета не означает, что сбор уже подключён. На телефоне доступны отчёты; приложение ChatGPT на iOS/Android не передаёт события этому расширению.

## Контроль и права

Владелец и Юра видят команду, отчёты, устройства, очередь сомнительных событий, исправления и историю действий. Сотрудник видит собственное время. Юра не может изменить код владельца или его профиль. Статус связи устройства не трактуется как доказательство работы. В отчёте показываются несинхронизированные события и время последней связи.

Неверные часы, повтор последовательности и события старше семи дней не увеличивают подтверждённый итог. Плохое событие не блокирует соседние корректные события. Администратор может отклонить событие или подтвердить проверенное время с причиной; для более старой истории предусмотрена ручная запись с проверкой пересечений. Локальные события прежнего подключения остаются в карантине исходного устройства и доступны для скачивания; автоматического переназначения другому сотруднику нет.

## Одноразовые коды по почте

Интеграция [Resend](https://resend.com/docs/api-reference/emails/send-email) включается серверными переменными `RESEND_API_KEY` и `MAIL_FROM` (проверенный отправитель). Коды действуют 10 минут, используются один раз, число попыток и отправок ограничено. Первый вход и восстановление через администратора доступны по выданному личному коду. Без настроенной почты интерфейс не обещает отправку письма. Реальные письма при автоматизированном тестировании не отправляются.

## Хранение и резервные копии

- D1 — основная база; R2 `BUCKET` — проверенные резервные копии.
- Закрытые интервалы старше восьми дней переводятся в архив итогов. Сырые события хранятся 90 дней. Итоги и коррекции — текущий и предыдущий календарные годы. При пересечении границы архивирования незавершённый интервал сохраняется целиком.
- При синхронизации устройства проверяется возраст последней копии. Если прошли сутки, создаётся новая копия с обратным чтением и SHA-256; Архивирование проверяется отдельно раз в сутки при синхронизации; ручные копии его не откладывают. В дни без синхронизаций запуск не гарантируется. Для строгого ежедневного расписания нужен внешний планировщик или поддерживаемый cron хостинга.
- Ручная копия доступна владельцу и администратору; полный файл скачивает только владелец. Снимок не содержит действующих браузерных сессий и OTP. События пишутся в R2 частями, скачивание объединяет их в один JSON.
- Восстановление выполняется сначала в **новую** изолированную базу: `python scripts/restore-backup.py snapshot.json restored.sqlite`. Скрипт проверяет схему и целостность, не перезаписывает существующие файлы, отключает устройства и сбрасывает коды работников (кроме владельца). После проверки восстановленную базу переносит оператор, затем заново выдаются коды и подключаются устройства. Автоматической замены рабочей базы через интерфейс нет.

## Разработка

Node >=22.13, pnpm 11.25.0, Python 3 для проверки и восстановления бэкапов. Сохраняйте lockfile.

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm run build
```

Интеграционные тесты используют отдельную SQLite in-memory базу, подмену D1/R2 и почты. Проверяют настоящие обработчики API. Не изменяют рабочие табели. JSON/SQL-миграции находятся в `drizzle/`; уже применённые миграции нельзя переписывать.

`node scripts/package-extension.mjs` пересобирает ZIP из `public/extension`. При смене адреса сначала обновите origin в `background.js`, `manifest.json` и инструкции расширения. Домен должен совпасть с фактическим HTTPS-адресом кабинета.

## Развёртывание

Проект работает в Sites/Cloudflare Worker с D1 и R2, аутентификация платформы — через доверенный шлюз. Сайт остаётся приватным. Подделанные внешние заголовки `oai-authenticated-user-*` нельзя принимать на обычном VPS. Контейнер/Docker для другого хостинга требует отдельной адаптации авторизации и базы; его в этой версии нет. Сервер .14 и чужие проекты не изменяются.

## Кошелёк

USDT TRC-20 / Trust Wallet находится в отдельном Falcon Messenger: `https://github.com/doolbarez/falcon-messenger`, версия исходников `f6d0430`. Это требование сохранено, кошелёк не связан с начислением зарплаты в Falcon Time. Ввод платежа выполняется в Falcon Messenger, подтверждение — в Trust Wallet. Для подключения адреса/баланса нужен WalletConnect/Reown Project ID и HTTPS-origin. Не хранить seed/private keys и не выполнять автоматические списания.
