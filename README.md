# Falcon Time → falconai.time

Цель: сервер `139.60.162.14`, отдельный контейнер `falcon-time`.
DNS: запись A для `falconai.time` → `139.60.162.14`, TTL600секунд.

## Что подготовлено

- Production Next.js standalone / Node24, frontend и backend в одном контейнере.
- Внутренний порт3000; наружу публикуется только `127.0.0.1:3187`, nginx обслуживает HTTPS443.
- SQLite WAL в отдельном томе `falcon_time_data`, резервные JSON-копии в `falcon_time_backups`.
- Запуск от UID1000 без root, без Docker socket, read-only rootfs, ограничение памяти768MB и1CPU.
- Миграции с контрольными суммами. Транзакции SQLite сохраняют атомарность старого D1 backend.
- Публичный первичный захват владельца отключён. Состав команды до входа не показывается.
- Вход по логину и личному коду. Код сотрудника выдаётся в разделе «Команда»; окно выдачи показывает и логин.
- Расширение из этого релиза работает с `https://falconai.time`, версия1.2.0. Старое расширение для Sites нужно заменить и переподключить.

## Текущий статус

Пакет подготовлен локально. Развёртывание на VPS НЕ выполнено: прямой доступ кIP из рабочей среды недоступен, а указанный вAGENTS.md GitHub runner `gh-runner` не имеет sudo и Docker. DNS, TLS и наличие свободного порта на VPS требуют проверки на сервере. Установщик делает эти проверки перед запуском.

Локально пройдены TypeScript,49 автоматических тестов, production build и HTTP smoke готовой сборки: вход, роли, CSRF за proxy, недоверие поддельным ChatGPT headers, rate limit по IP, сохранение базы и резервной копии после перезапуска, адрес нового расширения. ZIP расширения проверен на целостность. Независимое ревью: открытых P1/P2 нет; отдельно проверены общий бюджет OTP challenge и откат nginx config при ошибке. Docker image, TLS и серверная инфраструктура не проверены: здесь нет Docker и доступа к VPS.

## Первая установка оператором сервера

Нужны Docker с Compose v2, nginx, certbot, curl, openssl и root-доступ. Существующие сервисы не останавливаются. Если имя контейнера, том или виртуальный хост уже заняты, установщик останавливается. Зависимости ОС автоматически не устанавливаются.

1. Распакуйте готовый архив в `/opt/falcon-time`. В архиве находятся `runtime/`, `Dockerfile`, `compose.yaml`, `deploy/` и исходники `source/`. Готовый Dockerfile копирует проверенную сборку: npm-сборка на VPS не нужна. Требуется загрузить только базовый Docker-образ Node24. Сборка подготовлена под Linux x86_64; для другого CPU используйте Dockerfile в `source/`.
2. Если переносите действующий кабинет, сначала остановите ввод на старом адресе, создайте свежую полную JSON-копию через профиль владельца. Передайте её на сервер по защищённому каналу, например `/root/falcon-migration.json`, с правами600. Архив приложения НЕ содержит ваши данные, коды, SMTP/API-ключи или резервную базу.
3. Запустите из `/opt/falcon-time`:

```bash
sudo env LE_EMAIL='YOUR_CERTIFICATE_EMAIL' FALCON_IMPORT_BACKUP=/root/falcon-migration.json bash deploy/install.sh
```

Для совершенно нового кабинета уберите `FALCON_IMPORT_BACKUP`. Установщик создаёт случайный код владельца в `secrets/owner_code`; файл доступен контейнеру UID1000 и не печатается в лог. Логин владельца: `zafar`. Для перенесённой базы сохраняются прежние личные коды; старые сессии закрываются, устройства требуется подключить снова. Случайный код из файла в этом случае не заменяет старый код владельца.

Не передавайте код через URL, GitHub Actions inputs или публичные логи. После переноса закройте старый кабинет для сотрудников, чтобы не разделить учёт между двумя базами.

## Проверка после запуска

```bash
docker compose ps
curl --fail https://falconai.time/healthz
docker compose logs --tail=50 app
```

Войдите владельцем, заполните анкету при необходимости, проверьте команду и отчёты, создайте и скачайте резервную копию. Затем войдите тестовым сотрудником, подключите новое расширение, проверьте поступление события и ограничения роли. `/api/readiness` доступен только авторизованному администратору. Публичный `/healthz` показывает только `ok`.

Проверьте автопродление сертификата: `certbot renew --dry-run` и таймер вашей ОС. После продления нужен deploy-hook для reload nginx; используйте существующую политику сервера. Почтовые OTP необязательны; личные коды работают без почты. Для OTP задайте `RESEND_API_KEY` и `MAIL_FROM` через защищённый env-файл и добавьте `env_file` к сервису, затем пересоздайте только `app`.

## Резервирование и обновления

Автоматическая копия создаётся при heartbeat не чаще раза в сутки, ручная доступна администратору. Копия в другом Docker-томе находится на том же VPS: отдельно настройте защищённое копирование за пределы сервера. Не копируйте один активный SQLite-файл без WAL; используйте экспорт приложения илиSQLite backup API.

Перед обновлением сохраните свежий экспорт и предыдущий Docker image ID. Поскольку миграции меняют схему, откат образа проверяется на копии базы; при несовместимости импортируйте экспорт в НОВЫЙ том, затем переключайте контейнер. Не выполняйте `docker compose down -v`, `docker volume rm` или `docker system prune`.

Повторное применение `deploy/install.sh` намеренно запрещено. Для обновления соберите новый образ, проверьте новую копию базы и выполните `docker compose up -d --wait app`; существующие тома сохраняются. Nginx обновляется отдельно после `nginx -t`.

## Сборка из исходников

```bash
cd source
docker compose build
```

Для локальной проверки без Docker: `pnpm run build:vps`, затем `node scripts/prepare-vps-public.mjs .next/standalone`. Скопируйте `server/` и `drizzle/` внутрь standalone-папки. Запускайте `server/entrypoint.mjs` из её корня с `FALCON_ORIGIN`, `FALCON_DATA_DIR`, `FALCON_BACKUP_DIR`, `FALCON_OWNER_CODE_FILE`. Это production Node server, без Wrangler dev.

Изменять права `gh-runner` на полный sudo без отдельного решения не требуется. Публиковать исходники или данные в GitHub для установки этого архива не нужно.
